## Numbered implementation plan

1. **Define the trait data contract in the addon personality template.**
   - Add optional:
     ```lua
     likes = {
         places = { "forge", "mountain" },
         entities = { "dwarf", "gryphon" },
     }
     hates = {
         places = { "grave", "swamp" },
         entities = { "undead", "spider" },
     }
     ```
   - Define `actions["Likes"]` and `actions["Hates"]` as the corresponding weighted banter buckets, reusing the established `{ weight, lines }` structure.
   - Document case-insensitive, plain substring matching and the priority behavior.
   - Preserve the required `actions["Generic"]` fallback.

2. **Add small reusable matching and weighted-line helpers in `Loudmouth.lua`.**
   - Match non-empty keywords case-insensitively with `string.find(..., 1, true)`, avoiding Lua patterns.
   - For places, test each keyword against both `GetRealZoneText()` and `GetSubZoneText()`.
   - For entities, test against `UnitName("target")`; safely skip matching when no target/name exists.
   - Reuse the current Debug Mode behavior and `{ weight, lines }` probability semantics rather than creating a second probability model.

3. **Integrate place traits into pending-location resolution.**
   - Preserve the current exact zone/alias/subzone comments as highest priority and forced first-visit comments.
   - If no explicit zone/subzone comment matches, check hated-place keywords, then liked-place keywords.
   - Resolve a match to `actions["Hates"]` or `actions["Likes"]`, respectively.
   - Consume `PendingZoneComment` once for a matched trait visit. A selected weighted trait bucket should own that pending attempt even if its probability roll fails, rather than falling through to unrelated action dialogue.
   - Preserve current behavior when traits or corresponding dialogue buckets are absent.

4. **Integrate entity traits into normal action resolution.**
   - After pending-location handling, inspect the current target.
   - Select Hates before Likes if overlapping keywords match.
   - Priority becomes:
     1. explicit pending zone/subzone comment;
     2. pending hated-place reaction;
     3. pending liked-place reaction;
     4. hated-entity reaction;
     5. liked-entity reaction;
     6. named action dialogue;
     7. Generic fallback.
   - Apply the selected Likes/Hates bucket’s weight exactly as action weights are currently applied.
   - Retain the existing per-action cooldown key and ensure at most one line is emitted per `Trigger()` call.

5. **Update both existing personalities as concrete examples.**
   - Add in-character `likes` and `hates` keyword arrays covering both `places` and `entities`.
   - Add weighted `actions["Likes"]` and `actions["Hates"]` buckets with at least three short, voice-consistent lines.
   - Keep registration in `Loudmouth._RawPersonalities`, existing action data, and Generic fallbacks intact.
   - Do not add the trait pseudo-actions to `ActionOrderByClass`; they are contextual dialogue buckets, not castable macro actions.

6. **Verify compatibility, scope, and behavior.**
   - Confirm nil-safe handling for omitted trait tables, empty arrays, no target, and missing Likes/Hates action buckets.
   - Confirm all syntax remains Lua 5.1-compatible and no gameplay automation or newer WoW API is introduced.
   - Run lint and the required headless addon/UI smoke test.
   - Exercise deterministic examples with trait weights set to `1`: liked/hated zone and subzone transitions on the next macro press, and liked/hated target names during a cast macro.
